# SG-002 — Source groups

**Context.** API **2.2.0**, authored contract-first in `docs/OpenAPI.json` (five `/v1/me/source-groups`
operations present as `x-foresignal-status: planned`, tagged `x-foresignal-prompt: SG-002`,
`x-foresignal-permission: self.sources`; schemas `SourceGroupInput`/`SourceGroup`/`SourceGroupPage`/
`GroupCorrelation`/`GroupThreshold`; plus `BriefingScope.sourceGroupIds` and `TriggerRuleInput.sourceGroupId`).
This prompt **implements** that authored delta. Operations stay `planned`; `SG-004` activates them. Runs after
`SG-001` (a group's members may include the caller's custom sources).

**Goal.** A user holding `self.sources` creates named **source groups** — a member set of source ids (custom
or catalog) with its own correlation and notification threshold — through `/v1/me/source-groups`, and uses a
group two ways: as an **edition scope** (`BriefingScope.sourceGroupIds`, resolved to the group's member
sources when the edition runs) and as a **trigger scope** (`TriggerRuleInput.sourceGroupId`, ANDed with the
rule's sources/kinds). Groups are owned by the caller; another user's group is 404.

`SourceGroup` carries read-only `ownerUserId` (uuid), `editionId` (nullable), `createdAt`, `updatedAt`.
`listMySourceGroups` is cursor-paged (`SourceGroupPage` = `items` + `nextCursor`).

## Build

1. **`source_group` store.** Additive Flyway migration (next free `V{n}`) creating `source_group`:
   `id` (text PK, server-generated), `owner_user_id uuid not null` FK `"user"(id)` `on delete cascade`,
   `name`, `description` (nullable), `source_ids`/`kinds` (jsonb text arrays), `correlation` + `notification_threshold`
   (jsonb), `edition_id` (nullable FK to `briefing`), `created_at`/`updated_at`; index `(owner_user_id, id)`.
   Matching `@Entity SourceGroupEntity`, `SourceGroupRepository` (`findByIdAndOwnerUserId`,
   `findByOwnerUserIdOrderByCreatedAt` for cursor paging), and a `SourceGroupReassigner`
   (`UserOwnedConfigReassigner`).
2. **`SourceGroupService`.** Create/replace/get/list/delete, all keyed on `session.userId()`.
   - `sourceIds` validation: each member must be a known **catalog** source (`SourceRegistry.contains`) or an
     owned **custom** source (SG-001's store, scoped to the caller); any unknown id → 400 (mirror
     `RuleValidator`'s unknown-source 400). Server generates the group `id`; `ownerUserId` forced to the
     caller; a group the caller does not own (or a bad id) is **404**.
   - Persist `correlation` (`GroupCorrelation`) and `notificationThreshold` (`GroupThreshold`) as given,
     defaulting per the schema (`balanced`/`analytical`/`medium`; `warning`/false/null).
3. **`MySourceGroupsController`** (`@Tag("Sources")`) for the five ops, mirroring `SourceViewsController`’s
   session/401 and `EditionsController`’s 404-on-not-owned. Audit writes through the session/`AuditService`
   path.
4. **Use a group as an edition scope.** Add `sourceGroupIds` (`List<String>`) to `BriefingScope` (record field,
   `toMap`/`fromMap`, a convenience constructor). In `PlaceBriefingScopeResolver.resolve(...)`, resolve
   `sourceGroupIds` to the **union of member sourceIds** and merge into `sources` (same style as the `viewId`
   merge). **Fail closed:** a group that resolves to zero members, or a deleted group, must become
   "match nothing" (`nothing(...)`), never widen to all sources. Provide a `SourceGroupLookup` bean and inject
   it into the resolver the way `RegionFences`/place lookups are injected (do not change
   `DefaultScopeResolver`). When a group is turned into its own edition, set the group's `edition_id` and
   surface it as `SourceGroup.editionId`.
5. **Use a group as a trigger scope.** Add a nullable `source_group_id` column to `trigger_rule` (entity field
   + an additive migration, or fold into this prompt's migration). In `RuleValidator.validate`, read
   `sourceGroupId`, require the group exists and is owned by the **rule's owner** (a group not owned by the
   rule owner → 400), and let a `sourceGroupId` alone satisfy the "≥1 selector" check. Add `sourceGroupId` to
   `ValidatedRule` + its `applyTo`. In `RuleSpecs.compile(...)`, expand `sourceGroupId` to the group's member
   sourceIds and **union** them into the spec's source set (so `RuleSqlBuilder`/`TriggerEngine` need no change),
   failing closed to "match nothing" for an empty/deleted group. Resolve the owner mismatch explicitly: groups
   are keyed on `owner_user_id` (uuid) while rules carry `owner_principal_id` (string) — the `SourceGroupLookup`
   must map the rule's owning principal to that user's groups. Record the mapping in the CR.
6. **Access rules (two places).** Add `/v1/me/source-groups` and `/v1/me/source-groups/*` entries to
   `AccessPolicy.rules()` (`READ_ALWAYS_AUTHENTICATED`, in the `/v1/me/*` block), and regenerate
   `AccessPermissions.java` (`self.sources` already in the spec) so `AccessPolicyTest`/`AccessPolicySyncTest`
   agree.

## Tests to write (do not run)

- `SourceGroupCrudIT` — a `self.sources` user creates a group (owner forced, members validated, unknown id
  400), lists (cursor-paged) only their own, reads/updates/deletes it; another user's group is 404; an API
  token is 401.
- `SourceGroupEditionScopeTest`/`IT` — an edition with `sourceGroupIds` resolves to the union of member
  sources; an empty/deleted group yields "nothing", not "everything"; `editionId` is surfaced when a group is
  made into an edition.
- `TriggerSourceGroupScopeTest`/`IT` — a rule with `sourceGroupId` matches only the group's members (ANDed with
  any `sources`/`kinds`); a group not owned by the rule owner is 400; an empty group matches nothing; membership
  edits take effect without rewriting the rule.
