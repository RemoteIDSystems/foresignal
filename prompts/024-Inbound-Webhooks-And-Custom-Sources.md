## Objective

Let anything push data into Foresignal (SDR decoders, AIS-catcher, Home Assistant, scripts, n8n, agents, Alertmanager, CAP publishers, and every homelab tool that already speaks ntfy or Gotify). Pushed records enter the single v1.2 writer as `IngestRecord`s and get the same versioning, policies, live/touch semantics, change stream, triggers, search and retention as polled data. Custom sources declare their own time base, hash recipe and limits. On top of them, build the core of the **External Data Protocol** (EDP 1.0): self-describing third-party providers register with a manifest and push or serve items, so anyone can add a data source without changing Foresignal.

## Tasks

### 1. Custom sources (`ai.foresignal.inbound`)

- `CustomSourceEntity` (`custom_source`) + repository. Columns per Architecture §7.1 plus: `observed_at_mode`, `ttl_anchor`, `volatile_fields` jsonb, `significant_fields` jsonb, `title_field`, `field_specs` jsonb, `private` bool, `licence`, `records_per_minute` int, `formats` jsonb (per-format options, §3), `verifiers` jsonb (non-secret part), `verifier_secret_ciphertext`/`_nonce` (encrypted with `CredentialCipher`), `ingest_key_hash` (indexed, unique), `ingest_key_prefix`.
- **Descriptor built from the row** (`CustomSourceDescriptors.toDescriptor`): mode `PUSH`, `custom=true` (add the flag to `SourceDescriptor` if 004 did not), `historyTier=STANDARD` (fixed; custom sources are never TRACK), `observedAtMode` (UPSTREAM default, or RECEIVED), `ttlAnchor` (RECEIVED default, or OBSERVED), `recordTtl`, `volatileFields`, `significantFields`, `titleField`, `fieldSpecs`, `private` (prompt 008 fields; if absent, add them as optional descriptor fields), `licence`, `defaultBudget.perMinute = rateLimitPerMinute`, per-day budget `rateLimitPerMinute × 1440`, `zeroResultsNormal=true`.
- **`CustomSourceService`:**
  - **create:** id `^custom-[a-z0-9]+(-[a-z0-9]+)*$`, unique across all sources (static and dynamic); kinds follow the id pattern; field names (`tileProperties`, `searchFields`, `embedFields`, `volatileFields`, `significantFields`, `titleField`) are top-level keys matching `^[A-Za-z0-9_]{1,64}$`. Run the 004 registry validation and `IngestPolicyValidator` (§5.1) against the built descriptor. Generate the key (`eik_` + base64url(32 random bytes)), store SHA-256 hash + 8-char prefix, persist, `SourceRegistry.registerDynamic`, create settings with `enabled=true`, return the key once (`CustomSourceCreated`).
  - **update:** id immutable. Removing a kind that has current heads → 409 `KIND_IN_USE`. `observedAtMode` may change only while the source has no heads, else 409 `OBSERVED_AT_MODE_LOCKED`. Re-validate (a SAMPLED/LATEST effective policy with emptied `significantFields` → 400 `INGEST_POLICY_INVALID`), re-register, and publish `SourceRegistryChangedEvent` + `SourceSettingsChangedEvent` so the writer refreshes its `SourceIngestProfile`. A changed `volatileFields`/`significantFields` changes the hash recipe, and the writer's **lazy per-source recipe migration** (prompt 009, Core-Data-Model §4) runs before that source's next batch. Check that 009 implemented it; if not, add the recipe check there.
  - **delete:** unregister, delete row and settings; records age out through retention. **rotateKey.** **Startup:** register every persisted custom source before the scheduler, writer consumers and trigger engine start.
- `/v1/sources` shows custom sources with `custom=true`. Health uses push outcomes: success when the request was accepted, failure on a whole-request failure; zero-result detection off.

### 2. Ingest pipeline and auth

- **`IngestAuthenticator`** implements the `INGEST_KEY_OR_ADMIN` extension point from 003. Accepted credentials, checked in constant time against the hash:
  1. `X-Foresignal-Ingest-Key: eik_…`
  2. `Authorization: Bearer eik_…` (the token filter must hand `eik_` bearers on ingest paths to this authenticator, not reject them as unknown API tokens)
  3. `Authorization: Basic` with the key as the password (any username)
  4. compat only (§4): ntfy `?auth=` (base64 of an Authorization header value), Gotify `X-Gotify-Key` / `?token=`
  5. a bearer API token with `admin` scope
  Redact `auth`/`token` query parameters in every log line and in `fetch_log.url_redacted`.
- **`PushIngestService.ingest(sourceId, principal, List<NormalizedRecord>, receivedAt)`**, shared by every endpoint:
  - source must exist in PUSH mode (custom or built-in) → else 404; disabled → 409 `SOURCE_DISABLED`
  - request rate limit via `BudgetGovernor` (`perMinute`) → 429 + `Retry-After`; **records/min cap**: a second Bucket4j bucket per source sized `records_per_minute` (default 6,000, max 60,000), `tryConsume(n)` for the whole request, else 429 `INGEST_RECORD_RATE` + `Retry-After` and a `REFUSED` `fetch_log` row (reuse prompt 010's writer for non-OK rows)
  - body ≤ 5 MB (413), ≤ 10,000 records (400)
  - wrap each record as `IngestRecord(record, receivedAt, arrival)`; build `FetchLogEntry(trigger=PUSH, status=OK, principal, received_at, bytes, body_sha256, url_redacted, licence)`; submit one `IngestBatch` (queue timeout 30 s → 503 `INGEST_BUSY`) and await the `IngestOutcome`
  - `principal` = `ingest-key:<prefix>`, `token:<name>`, or `compat-ntfy:<prefix>` / `compat-gotify:<prefix>`
  - count usage (requests, bytes) like upstream traffic, plus `UsageMeter.recordIngest`
- **Response:** `IngestOutcome` (v1.2 shape: `seen, persisted, live, touched, touchesThrottled, late, skipped, rejected, fromSeq, toSeq, byReason, rejections[{index, externalId, reason}]`). Keep `changed` as a deprecated alias of `persisted`. HTTP 200 when the request itself was valid, even with per-record rejections.
- **Time base:** under UPSTREAM a record without `observedAt` is rejected `MISSING_OBSERVED_AT` (no silent default); under RECEIVED the writer stamps it. Never mix within a source.

### 3. IngestFormat SPI (`ai.foresignal.inbound.format`)

- `interface IngestFormat { String id(); Set<MediaType> mediaTypes(); ParsedIngest parse(IngestRequest req, SourceDescriptor d, FormatOptions opts); }` where `IngestRequest` carries raw body bytes, headers and query; `ParsedIngest` = records + per-item rejections. Formats are Spring beans collected by `IngestFormatRegistry`.
- **Endpoints:** `POST /v1/ingest/{sourceId}` (auto: `native` for JSON) and `POST /v1/ingest/{sourceId}/{format}`. Unknown format → 404 `FORMAT_UNKNOWN`. Reserve `media` and `rasters` (prompt 054 registers them) and `mapping-preview` (059). `GET /v1/ingest/formats` (admin) lists formats with their options.
- **`native`:** GeoJSON FeatureCollection (`id` → externalId, required; properties `kind` (optional with a single kind), `observedAt`, `eventTime`, `validUntil` (upstream-asserted only), `tombstone`, `quality`; the rest → payload) or `{"records": [...]}` in `NormalizedRecordPreview` shape.
- **`alertmanager`** (webhook payload `version: "4"`): one record per `alerts[]` item. externalId = `fingerprint`; kind = option `kindLabel` value, else the single kind; `eventTime = startsAt`; `observedAt = status == firing ? startsAt : endsAt` (monotonic per fingerprint; repeats are equal timestamps → touches); payload `{status, labels, annotations, generatorURL, receiver, groupKey}`; geometry from labels `latitude`/`longitude` (or `lat`/`lon`) when both parse. Option `resolved: tombstone|record` (default `tombstone`). Alertmanager cannot sign; it authenticates with Bearer or Basic via `http_config`.
- **`cloudevents`:** structured (`application/cloudevents+json`), batch (`application/cloudevents-batch+json`) and binary mode (`ce-id`, `ce-source`, `ce-type`, `ce-subject`, `ce-time` headers, body = data). externalId = `subject` ?? `source + "/" + id`; kind from option `typeKinds` (map of CE `type` → kind), else the single kind, else reject; `observedAt = time`; payload = `data` (object) or `{"data": value}` plus `{ceType, ceSource}`; geometry from `data.geometry` (GeoJSON) or `data.lat`/`data.lon`. Answer the webhook abuse-protection handshake: `OPTIONS` with `WebHook-Request-Origin` → 200 with `WebHook-Allowed-Origin` (and `WebHook-Allowed-Rate` = the source's per-minute budget).
- **`cap`** (CAP 1.2 XML, `application/cap+xml` or `application/xml`): write the shared parser `ai.foresignal.format.cap.CapParser` here (prompts 067 and 089 reuse it). Secure XML only (DTDs and external entities disabled). `msgType Alert` → record externalId = `identifier`; `Update` → new record plus tombstones for every `references` entry (`sender,identifier,sent`); `Cancel` → tombstones only. `observedAt = sent`; `eventTime = info.onset ?? info.effective`; `validUntil = info.expires`. Geometry: `polygon` pairs are **"lat,lon"** (swap to lon/lat), `circle` "lat,lon radiusKm" → 64-segment polygon; several areas → MultiPolygon. Payload: `event, headline, description, instruction, severity, urgency, certainty, areaDesc, sender, status, msgType, language, geocodes`. `status` other than `Actual` is rejected unless option `acceptNonActual=true`.
- **`mapping`:** minimal `RecordMapping` (stored per custom source under `formats.mapping`): `recordsPath`, `externalId`, `kind`, `observedAt` (+ `observedAtFormat`: ISO, epoch-s, epoch-ms), `lat`/`lon` or `geometry`, `payload` (list of `{from, to}`), all as JSON Pointer paths. Class names `RecordMapping` and `RecordMappingEngine`; prompt 059 extends them with units, preview, LLM drafts and presets.
- **Per-format signature verifiers** (`SignatureVerifier` SPI), configured per source per format under `verifiers.{format}`: `none`; `hmac-sha256` (header configurable, default `X-Signature-256`, value `sha256=<hex>` over the raw body); `standard-webhooks` (`webhook-id`, `webhook-timestamp`, `webhook-signature: v1,<base64>` over `id.timestamp.body`, ±5 min tolerance, replayed `webhook-id` rejected for 10 min); `foresignal` (`X-Foresignal-Timestamp` + `X-Foresignal-Signature: sha256=HMAC("<ts>.<body>")`, the scheme of Foresignal's own webhook channel, for Foresignal-to-Foresignal). When a verifier is configured the signature must verify (401 `SIGNATURE_INVALID`) in addition to the key, unless `keyOptional=true`, in which case a valid signature alone authenticates. Secrets are write-only.

### 4. ntfy- and Gotify-compatible publish

Paths outside `/v1` (add explicit `AccessPolicy` rules, auth = §2 `IngestAuthenticator`; the `topic`/key resolves the source):
- **ntfy:** `PUT|POST /compat/ntfy/{topic}` (body = message; headers `X-Title`/`Title`/`t`, `X-Priority`/`Priority`/`p` (1–5 or min…max), `X-Tags`/`Tags`/`ta`, `X-Click`), `GET|POST /compat/ntfy/{topic}/{publish|send|trigger}?message=&title=&priority=&tags=`, and JSON publish `POST /compat/ntfy` with `{"topic", "message", "title", "priority", "tags", "click"}` (Uptime Kuma uses this shape). `topic` = the custom source id. Respond with an ntfy-style JSON message object (`id`, `time`, `event: "message"`, `topic`, `message`).
- **Gotify:** `POST /compat/gotify/message` (JSON or form: `title`, `message`, `priority`, `extras`); the key identifies the source. Respond with a Gotify message object (`id`, `appid: 1`, `date`, …).
- Mapping for both: kind = the source's single kind (else `notification`, which must be one of its kinds); externalId = `X-Foresignal-External-Id` header, ntfy tag `id=<x>`, or Gotify `extras["foresignal::record"].externalId`, else a ULID per message; payload `{title, message, priority, tags, click, topic}`. Recommend `observedAtMode=RECEIVED` and a TTL for these sources in the docs.

### 5. External Data Protocol (EDP 1.0) core (`ai.foresignal.inbound.edp`)

Implement `docs/External-Data-Protocol.md` §1–§4 and §7 exactly; the schemas are in `docs/OpenAPI.json` (`Edp*`, `ExternalSource*`).

- **Manifest → custom source:** `EdpManifestService.register(manifest, options)` validates the manifest (protocol minor ≤ `edp.maxMinor` (1.0 → 0) else `PROTOCOL_UNSUPPORTED`, at least one delivery mechanism, unique stream ids, layer streams carry `feature`/`event` and a geometry, ids, kinds, JSON Schema 2020-12 `payloadSchema`s compiled with networknt `json-schema-validator` (Apache-2.0; verify the version), transport, `presentation` hints) and creates a custom source `ext-{source.id}` through `CustomSourceService` with a descriptor built from it: kinds from the streams, `fieldSpecs` from `payloadSchema`, `titleField`, `significantFields`, `volatileFields`, `recordTtl`, analytic retention class, `private`, licence (with `redistribution` → default egress), `originator` (add the optional descriptor field if 004 did not; 116 reads it), and `access` (route, terms summary, fragility). Store the manifest (`external_source`: `source_id`, `manifest` jsonb, `manifest_sha256`, `state` `pending | active | suspended`, `registered_via` `operator | registration-token`, `approved_by`, `approved_at`, `pull_cursor`, `last_item_at`, `stats` jsonb).
- **Registration:** `POST /v1/external/sources` (admin; `{manifest}` or `{manifestUrl}`, fetched once through `UpstreamClient` with the 043-style SSRF guard, plus `approve`), `POST /v1/external/registration-tokens` (admin; `fsx_` + base64url(32 bytes), hash stored, `expiresAt`, `maxUses` default 1, optional `sourceIdPrefix`), `POST /v1/external/register` (registration token as bearer; creates the source `pending`, returns the ingest key once), `POST /v1/external/sources/{sourceId}/approve`, `/suspend` (admin), `DELETE /v1/external/sources/{sourceId}` (admin; deletes the custom source), `GET /v1/external/sources` and `GET /v1/external/sources/{sourceId}` (admin; manifest, state, per-stream stats, last validation errors, pull status).
- **Manifest updates:** `PUT /v1/external/sources/{sourceId}/manifest` (admin, or the source's ingest key). Additive changes apply at once; any change to streams, kinds, `payloadSchema`, `itemType` or `mode` returns the source to `pending` (its records stay).
- **Items:** `EdpItemMapper` maps each item to a `NormalizedRecord` (`externalId = {stream}:{id}`, kind = the stream's kind; `feature`/`event` geometry and times; `observation` → payload `{seriesKey, t, value, unit, knownAt}` (093's series model reads it later); `document` → payload with `documentType`, `text`, `title`, `url`, `author`, `language`, `publishedAt`, `about`, `media`, `engagement`; `forecast` → payload `{question | questionRef, probability | quantiles, madeAt}`; `delete` → tombstone; `status` → source health only). Records from `atomic` streams carry `edp.mode = atomic` in their metadata and their kinds are hidden from default tile layer lists (still queryable, searchable and rule-able); `layer` streams are ordinary map layers with the manifest's `presentation` exposed on `GET /v1/external/sources/{sourceId}` and in the kind's TileJSON metadata.
- **Push:** `POST /v1/external/sources/{sourceId}/items` (ingest-key auth from §2), `application/json` batch or `application/x-ndjson`; checks the batch (`protocol` minor ≤ the manifest's, `sourceId` equal to the source when present else `400 SOURCE_MISMATCH`, size, depth 32, string and media limits) and validates each item in the protocol's order (§3.1: `type` matches `itemType`, item schema, `properties` against `payloadSchema`, RFC 7946 geometry with bounds, ring closure, ≤ 10,000 vertices and the stream's geometry type, `t` period formats with one granularity per series, forecasts with a question and a probability or non-decreasing quantiles); hands the valid ones to `PushIngestService`; returns `EdpIngestResult` (`accepted`, `rejected[{index, stream, id, reason, schemaErrors}]`, `outcome`). Pending or suspended sources → 409 `SOURCE_PENDING_APPROVAL` / `SOURCE_SUSPENDED`. **Snapshots** follow §3.2 exactly: stage ids per `snapshot.id` (table `edp_snapshot_stage`), apply `ABSENT_FROM_SNAPSHOT` tombstones only for a final, fully received and validated snapshot of that scope within `snapshotWindow` while the stream reported no unhealthy `status`, and hold deletions above `maxAbsentRatio` (source `degraded`, operator can allow once); a failed or partial snapshot removes nothing.
- **Time and origin:** store provider times as given and record `receivedAt`; expose `effectiveKnownAt = max(knownAt, receivedAt)` (and the same for `publishedAt`, `madeAt`) for 093, 116 and 122 to use; reject `observedAt` more than 5 min in the future. Store `origin` (item) and the manifest originator on each record (`edp.originator`, `edp.upstreamId`, `edp.derivedFrom`) for 116.
- **Security boundary (§7):** every provider URL goes through an `EdpUrlGuard` (HTTPS unless the source allows private networks; resolve once and pin the connection to the vetted address; refuse loopback, link-local, private, CGNAT and metadata ranges unless `allowPrivateNetwork` is set on that source; same-host redirects only, ≤ 3, each re-vetted; timeouts and 5 MB caps). `payloadSchema`s are limited to 64 KB, local `$ref`s only, `pattern`s ≤ 256 chars compiled with RE2/J (BSD; verify the version) through the validator's regular-expression hook, and a 2 s validation budget per batch. `private` and the licence's egress are set on the descriptor so the existing egress and TLP rules cover every derived product.
- **Pull:** when the manifest declares `transport.pull`, register a POLLING collector for the source (010 scheduler, 005 budgets, credentials through `PUT /v1/sources/{sourceId}/credentials`) that calls `itemsUrl?cursor=&limit=500`, follows `nextCursor`, stores the cursor, and maps provider failures to health. Store `transport.search` when declared; 137's cue service calls it.
- **Validation:** `POST /v1/external/validate` (agent) checks a manifest and/or items without storing anything and returns `EdpValidationReport`. Write `src/test/resources/edp/conformance/` fixtures (valid and invalid manifests and batches for every item type) and keep `scripts/export-edp-schemas.py` (already in the repository; it extracts the `Edp*` component schemas from `docs/OpenAPI.json` into `docs/protocol/edp-1.0/*.schema.json`) wired into the spec workflow; `GET /v1/external/protocol` (open) returns the protocol version and item types, `GET /v1/external/protocol/schemas/{name}` (open) serves the exported files.
- **Status items** set the source's health (`degraded`, `blocked`, `layout-changed`, `geo-restricted` → 006 reasons) without creating records.
- Prompt 138 adds bindings for atomic streams (series, canonical families, social and news pipelines, evidence, indicators, forecasts, places, situations, chronicles) and the provider kit.

## Acceptance criteria

- A curl POST of a FeatureCollection to a new custom source produces records in `/v1/records`, change events on SSE, and alerts when a rule matches.
- An Alertmanager v4 payload, a CloudEvent, a CAP alert and an ntfy publish each create the expected records; a resolved alert or CAP Cancel tombstones them.
- A provider registered by manifest pushes `feature`, `event`, `observation`, `document`, `forecast`, `delete` and `status` items that land as versioned records (or health), with per-item validation errors; a pull-mode provider is polled with cursors; nothing from a pending source is stored.
- Compiles.
