## What was added

- **`docs/OpenAPI.json` at `2.1.0`.** Six operations, each `x-foresignal-status: planned` and
  `x-foresignal-prompt: NP-001`:
  - `getTranslationSettings` and `updateTranslationSettings`: `GET`/`PUT /v1/settings/translation`, `admin`,
    `system.settings`.
  - `getMyNewsSubscriptions` and `updateMyNewsSubscriptions`: `GET`/`PUT /v1/me/news-subscriptions`, `read`,
    `self.sources`, always authenticated.
  - `listMyEditions`: `GET /v1/me/editions`, `read`, always authenticated, no permission (like `getMe` and
    `listMyTokens`), cursor-paged (`cursor`, `limit` 1–200, default 50).
  - `getEditionSite`: `GET /v1/editions/{briefingId}/site`, `read`, `intel.read`, open while `openReads` is on
    (`security: [{}, bearer]`). It mirrors `getBriefingPodcast` and `getLatestBriefingRun`:
    - it returns `text/html` by default and `EditionSite` with `Accept: application/json` or `?format=json`;
    - it has a strong ETag, `Last-Modified`, `If-None-Match` and 304;
    - it reaches by feed key at `/v1/k/{key}/editions/{briefingId}/site` and by share link.
- **New schemas:**
  - The seven the prompt names: `TranslationSettings`, `TranslationSettingsInput`, `NewsSubscription`,
    `NewsSubscriptionView`, `NewsSubscriptionUpdate`, `EditionSummary` and `EditionSite`.
  - The two its extensions need: `DeliveryTarget` (`kind`, `channelId`, `format`, `options`) and
    `BreakingNewsConfig` (`enabled`, `ruleIds`, `minSeverity` as the existing `Severity`, `cooldownMinutes`).
- **Additive fields.** Every new field is optional, so a 2.0.0 client stays valid. Each schema's
  `x-foresignal-extended-by` and `x-foresignal-property-prompts` name the prompt that implements each field.
  - `BriefingInput`: `outputLanguage` (NP-003), `deliveryTargets` (NP-004), `site` with `enabled` and `shareable`
    (NP-005), `breakingNews` (NP-006), and `includeProvenance` and `includeCorroboration` (NP-007).
  - `Briefing`: a read-only `ownerUserId` (NP-003).
  - `AskCitation`: `provenance` (`refs` as `ObjectRef[]`, plus `reason`) and `corroboration` (`evidenceQuality`,
    `independentSources`, `credibility`, `reliability`, using the existing enums) (NP-007). Both are described as
    set only on briefing-run citations.
  - `NewsArticle` and `NewsStory`: `targetLanguage`, `translatedTitle`, `translatedExcerpt` and
    `translationProvenance` (`engine`, `model`, `at`) (NP-002).
- **Changelog:** a `2.1.0` entry is appended to `info.x-foresignal-changelog`, listing every operation, schema and
  field above. NP-002 to NP-007 are told not to touch the changelog, so this entry covers the whole campaign.
- **`AccessPolicy`:** three `READ_ALWAYS_AUTHENTICATED` rules in the `/v1/me` block, and a `READ` rule for
  `GET /v1/editions/*/site` next to the podcast rule.
  - `/v1/settings/translation` is `admin` under the existing `/v1/settings/**` rule, the same way every other
    settings pair is handled.
  - The class javadoc gains an NP-001 paragraph.
  - I checked by reading the code that no earlier, broader rule catches the new paths. The only `/v1/**` match is the
    deny-by-default fallback.
- **`AccessPermissions`:** regenerated by `scripts/generate-access-permissions.py`.
- **Version:** `2.1.0` in all three places the guard checks (`info.version`, `ApiVersionTest.RELEASE`, Gradle
  `version`). The frozen `docs/api/v1.0.0/OpenAPI.json` is untouched.
- **Postman:** regenerated.
- **Tests (written, not run):**
  - `ApiVersionTest`: `RELEASE` is `2.1.0`, and a new `changelogEndsWithTheRelease` checks that the newest changelog
    entry is the release.
  - `AccessPolicySyncTest`: a new `newspaperOperationsHavePolicyEntries` checks the six operations by
    `operationId`. Each must be a route, and the policy must grant exactly its scope, always-authenticated flag and
    permission. It also spot-checks the three resolved requirements. The existing every-route checks already cover

## Decisions and questions for the owner

1. **Edition CRUD reuses the briefing endpoints.** The contract adds only `listMyEditions`. An edition is created,
   changed, run and deleted through `createBriefing`, `updateBriefing`, `runBriefing` and `deleteBriefing`, which are
   `agent` scope today. A plain signed-in user without `agent` therefore cannot create their own edition. Say if you
   want `/v1/me/editions` CRUD (self scope) instead.
2. **`x-foresignal-prompt` is `NP-001` on all six operations, as this prompt's table says.** `NP-000`'s standing
   rules, `docs/Conventions.md` and the R2 precedent use this field for the prompt that *implements* the operation.
   These documents disagree; which should change?
3. **No prompt implements `getMyNewsSubscriptions` or `updateMyNewsSubscriptions`.** NP-002 to NP-007 never mention
   them. NP-003 (editions scoped to the user's data) is the natural home. Say whether to add them to NP-003.
4. **The `SpecAnnotationsTest` guard cannot pass with these prompt ids.** `promptNumber()` accepts only `\d{3}`, and
   `pending-operations.txt` accepts only `<operationId> NNN`. Every `R2-*` operation already fails
   `everyOperationIsAnnotated`, and the six `NP-001` operations now do too. Like R2, I left the pending list empty,
   so `OpenApiContractIT` ("authored minus pending equals generated") is red until NP-007, as it was during R2. The
   guard needs to learn the `R2-NNN`/`NP-NNN` ids. Say whether a prompt should own that.
5. **Wire shapes the prompts need that this contract does not author.** I did not invent these:
   - **NP-005:** a share link to the site needs a new `ShareLinkCreate.targetType` (and `SharedContent.targetType`)
     value, for example `edition`. Today's enum is `record`, `alert`, `view`, `track`, `briefing-run` and `export`.
   - **NP-006:** "a flag on the run" marking a breaking-news edition has no `BriefingRun` field. `breaking: boolean`
     is the obvious one.
   - **NP-004:** "each target is recorded on the run", but `BriefingRun.deliveries` is an integer. Per-target results
     need a field.
   - **NP-002:** `translatedBody`. `NewsArticle` is metadata only ("no body"), so no body is stored to translate.
     I left `body` out of `TranslationSettings.fields` (`title`, `excerpt`; extensible).
   - Because NP-002 to NP-006 may not touch the changelog, any of these additions either goes into NP-001's 2.1.0
     entry now or needs that rule relaxed. Which do you want?
6. **Shapes I chose where the prompt names a schema but not its members.** Please confirm or correct:
   - **`NewsSubscription`** is `{type: outlet|language, id}`. A list with no entries of a type is no restriction of
     that type.
   - **`TranslationSettings`:**
     - `enabled`, `targetLanguages` (BCP 47, at most 10), `fields`;
     - `engine`, extensible and `llm` only;
     - `budget {window: hour|day|month, capUsd}`, reusing the 162 spend windows;
     - `minSourceLanguageConfidence` (default 0.8);
     - a read-only `spend` (`LlmSpendWindow`).
   - **`site`** is `{enabled, shareable}`.
   - **`EditionSummary`** carries `latestRunId` and `siteUrl`.
7. **Provenance and corroboration live on `AskCitation`.** The contract has no `BriefingSection` wire schema;
   sections are free-form under `DigestStats.sections`, and a run's per-item evidence is its `citations`. Adding
   optional fields to `AskCitation` is additive on the wire and in the SDKs. The cost is that the same schema also
   serves Ask and alerts, where the fields are documented as absent. The alternative is a `BriefingCitation`
   subtype, which renames the Dart type of `BriefingRun.citations`.
