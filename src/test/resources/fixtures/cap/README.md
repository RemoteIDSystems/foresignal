# CAP conformance fixtures (prompt 067)

Hand-made OASIS CAP documents for `CapParserTest`, `CapGeometryTest` and `CapRecordMapperTest` (the shared CAP
support in `ai.foresignal.source.formats.cap`). Real captured CAP lives under `../tsunami-warnings/`.

| File | What it is |
|---|---|
| `polygon.xml` | CAP 1.2 Alert with two areas: a closed polygon with a SAME geocode, and an open ring (closed by the parser); effective, onset and expires; an allowlisted `VTEC` and a non-allowlisted parameter. |
| `circle.xml` | A 10 km circle and a zero-radius circle (a Point). |
| `geocode-only.xml` | An area with only UGC and SAME geocodes (no geometry). |
| `multi-language.xml` | Two info blocks, `fr-CA` first and `en-CA` second. |
| `references.xml` | An Update referencing two earlier messages (the later first) and one malformed triple. |
| `cancel-no-info.xml` | A Cancel with no info block. |
| `xxe.xml` | An external-entity (XXE) attempt through a DOCTYPE. |
| `billion-laughs.xml` | An entity-expansion attempt through a DOCTYPE. |
| `cap11.xml` | A CAP 1.1 alert (accepted, version recorded). |
| `cap10.xml` | The same in the CAP 1.0 namespace (refused). |
| `missing-sender.xml` | `polygon.xml` without `sender` (refused). |
| `embedded-atom.xml` | Captured, not hand-made: the first two entries of Brazil's MDR feed (`idapfile.mdr.gov.br/idap/api/rss/cap`, 2026-10-22), whose Atom entries carry whole CAP 1.2 alerts instead of links. |

The 3 MB oversize alert is generated by `CapParserTest` rather than committed.
